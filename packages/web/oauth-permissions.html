OAuth & Permissions

Exactly what permissions we request from each connected platform and why — maintained for platform review by Meta, Google, LinkedIn, TikTok, X, Pinterest, Threads, Canva, Dropbox, and WordPress.

Thuthu (Pty) Ltd t/a myPilotPost  ·  Reg. No. 2025/102758/07

myPilotPost connects to social media and productivity platforms on your behalf using OAuth 2.0 — an industry-standard authorisation protocol that allows you to grant specific, revocable permissions to a third-party application without sharing your account password. This page is relevant to users of myPilotPost and to the platform review processes of Meta, Google, LinkedIn, TikTok, Canva, and other connected services.

We request only the permissions necessary to deliver the specific features you use. We never request permissions beyond what is required for stated functionality.

How OAuth Works

  • Step 1: You click Connect within the myPilotPost Integration Hub
  • Step 2: You are redirected to that platform's official authentication and authorisation screen — hosted by that platform, not by us
  • Step 3: You review the permissions being requested and choose to approve or deny
  • Step 4: If approved, the platform issues an access token to myPilotPost — your password is never transmitted to us at any point
  • Step 5: We store this token encrypted, scoped to your brand and connected account within our Cloudflare infrastructure
  • Step 6: You can revoke access at any time — either from within myPilotPost or directly from the connected platform's settings

Permissions We Request — By Platform

The table below documents every OAuth permission (scope) requested from each connected platform, the reason for the request, and key account requirements. All scope lists reflect the live configuration in our OAuth provider registry.

Facebook Pages

Account requirement: You must be an admin of a Facebook Page. Personal profiles cannot be connected for publishing. Business Manager / Advanced Access is required for production use of pages_manage_posts.
OAuth ScopeAccess TypeWhy We Request It
pages_show_listReadTo display your available Facebook Pages during the account connection flow so you can select which Page to connect
pages_read_engagementReadTo retrieve post engagement metrics — likes, comments, shares, reach — for your Mission Analytics dashboard
pages_manage_postsPublishTo publish scheduled posts to your connected Facebook Page via the Meta Graph API
business_managementReadTo retrieve the list of Pages and assets associated with your Business Manager account during the connection flow

We do not request pages_messaging, ads_management, or any permission enabling inbox, ad, or personal profile access.

Token behaviour: Meta issues long-lived user access tokens (60 days) and long-lived Page access tokens (no expiry). Token refresh is handled server-side and transparently. Tokens are scoped to the specific Page selected during connection and stored encrypted in our Cloudflare infrastructure.

Data stored: Page ID, Page name, and OAuth access token (encrypted). Engagement metrics retrieved via the API are stored for display in Mission Analytics and are not shared or sold.

Instagram

Account requirement: An Instagram Business Account or Creator Account connected to a Facebook Page is required. Personal Instagram accounts are not supported. Advanced Access (Meta App Review) is required for instagram_content_publish in production.
OAuth ScopeAccess TypeWhy We Request It
instagram_basicReadTo verify the connected Instagram Business/Creator account identity and retrieve basic profile data for display within myPilotPost
instagram_content_publishPublishTo publish scheduled posts, images, videos, carousels, and Reels to your connected Instagram Business or Creator account via the Content Publishing API
pages_show_listReadTo discover Facebook Pages linked to your account, which is required to connect an Instagram Business Account

Threads

Account requirement: A Threads account linked to your Instagram account is required. Threads uses the Meta OAuth infrastructure but operates its own separate token and API system (graph.threads.net). Long-lived token exchange is required — short-lived tokens (1 hour) are immediately exchanged server-side for long-lived tokens (60 days).
OAuth ScopeAccess TypeWhy We Request It
threads_basicReadTo verify the connected Threads account identity, retrieve the username, and confirm account availability for publishing
threads_content_publishPublishTo publish scheduled posts to your Threads account via the Threads Content Publishing API

Token behaviour: Threads issues short-lived tokens (1 hour) upon OAuth callback. myPilotPost immediately exchanges these for long-lived tokens (approximately 60 days) server-side using the th_exchange_token grant. Threads does not issue refresh tokens — when the long-lived token expires, reconnection is required. We surface this to the user before expiry.

Data stored: Threads user ID, username, and access token (encrypted, 60-day lifecycle). We do not store or access Threads DMs, replies from other accounts, or any private content. Revocation: Threads app settings → Connected apps → Remove myPilotPost, or via Instagram Settings → Apps and Websites.

What We Do NOT Do With OAuth Access

These restrictions are enforced by the permission scopes we request. We do not request permissions that would enable these actions, and we do not perform them.
  • We never read or access direct messages, private inboxes, or private conversations on any connected platform
  • We never publish content without explicit user scheduling and confirmation via the myPilotPost Launch Pad — no AI-initiated or background publishing occurs
  • We never follow, unfollow, like, comment on, or interact with third-party accounts or content on your behalf
  • We never sell, share, licence, or otherwise expose your OAuth tokens or connected account data to any third party, except Cloudflare as our infrastructure provider
  • We never use the OAuth access of one connected platform to access data from another
  • We never retain OAuth tokens after a connected account is disconnected — tokens are deleted immediately upon disconnection
  • We do not use OAuth access to scrape, harvest, or store data from connected platforms beyond what is necessary for the features described in this document
  • We do not access platform data from accounts you have not explicitly connected — no cross-account access occurs

How Tokens Are Stored

  • OAuth access tokens are encrypted before storage using Cloudflare's infrastructure encryption layer
  • Tokens are scoped per brand and per connected account — cross-brand access is architecturally prevented at the API and database layer
  • Access tokens are never logged in plaintext in application logs or error reports
  • Token refresh (where supported by the connected platform) is handled server-side and transparently — you do not need to reconnect unless the platform revokes the token or the token expires without a refresh grant
  • Tokens are stored in Cloudflare D1 (relational) and/or KV, both encrypted at rest by Cloudflare's storage layer
  • On account deletion, all stored OAuth tokens are deleted within 30 days of confirmed deletion

Revoking Access

From myPilotPost

  • Navigate to Control Tower → Integration Hub
  • Locate the connected account you wish to disconnect
  • Select Disconnect — the access token is deleted from our system immediately

From the Connected Platform Directly

Revoking directly from the platform will invalidate the token in our system on the next API call. We recommend also disconnecting from within myPilotPost to ensure our stored token record is removed.

  • Facebook / Instagram: facebook.com → Settings → Security & Login → Apps and Websites → Remove myPilotPost
  • Threads: Threads app → Privacy → Connected apps → Remove myPilotPost (or via Instagram Settings → Apps and Websites)
  • Google (YouTube / Analytics / Business Profile / Drive): myaccount.google.com → Security → Third-party apps with account access → Remove myPilotPost
  • LinkedIn: linkedin.com → Settings & Privacy → Data Privacy → Permitted Services → Remove myPilotPost
  • X (Twitter): twitter.com/settings/connected_apps → Revoke access for myPilotPost
  • TikTok: TikTok app → Profile → Settings → Privacy → Manage app permissions → Remove myPilotPost
  • Pinterest: pinterest.com → Settings → Security → Apps → Remove myPilotPost
  • Canva: canva.com → Account Settings → Connected Apps → Disconnect myPilotPost
  • Dropbox: dropbox.com → Account → Security → Apps → Revoke myPilotPost
  • WordPress: wordpress.com → Account → Security → Connected Applications → Revoke myPilotPost
